# CMS synchronization — Registry 1.4.0

Frontend-side contracts are ready. **The separate CMS repository was not modified; its integration/confirmation remains pending.** Parent 0.33.0 ships Registry 1.4.0 with 29 CMS capabilities / 26 Page Schema block types. Content Contract stays 2.1.0 and Publish Package stays 1.0.0: existing payloads remain valid. Do not downgrade to the old review snapshot.

The single authoring source remains `wp-content/themes/solo-to-china/content-contract/component-registry.v1.json`. Run `scripts/generate-component-catalog.ps1` to regenerate public schemas, bundled copies and component documentation. Never edit generated JSON as an independent source. Additions are selectable; the frontend never inserts article sections based on the guide category.

| Capability | New authoring choices | Defaults / compatibility |
|---|---|---|
| `quick_facts` | `compact`, `detailed` | Existing `default` valid; same facts data |
| `steps` | `screenshots`; optional screenshot records keyed by step | Existing ordered text steps unchanged |
| `route_timeline` | Transport mode, travel time, note, canonical entity key | Optional; no invented duration/distance |
| `image` | Focal preset, natural/landscape/portrait frame, enlarge | Natural frame, center focus; ordinary Media attachment metadata retained |
| Hero presentation | `compact`, `image-led` | Old variants still accepted; no actual image renders a compact header |
| `place_info_card` | Canonical entity, bilingual context, optional Media image and guide/Taxi actions | No known entity or published guide: omit the empty block |
| `annotated_image` | Media image, alt, caption, numbered x/y/text annotations | x/y in [0,1]; image uncropped, visible text legend; no CMS CSS |
| `related_guides` | Explicit post IDs or entity keys + guide type | Published only, deduplicated, current post excluded, empty block omitted |

Use real attachment IDs from the same WordPress site. Illustration IDs in examples are placeholders and are remapped by local fixtures. Normalized annotation coordinates refer to the entire uncropped image. Route notes and arrival facts must be editorially supplied, not generated by frontend logic.

Screenshot steps accept at most one screenshot per existing step. Duplicate or out-of-range step references are rejected before writing. The CMS API validates Media references for screenshot steps, place information images and annotated images as well as ordinary image blocks.

Example Page Schema blocks (within the existing publish package):

```json
[
  {"type":"quick_facts","variant":"compact","data":{"items":[{"label":"Area","value":"Central Beijing"}]}},
  {"type":"place_info_card","variant":"default","data":{"entity_key":"forbidden-city","description":"Use the guide to plan your visit."}},
  {"type":"annotated_image","variant":"default","data":{"media_id":123,"alt":"Entrance map supplied by the editor","annotations":[{"x":0.35,"y":0.62,"text":"Confirm the entrance shown in your booking."}]}},
  {"type":"related_guides","variant":"default","data":{"entity_keys":["beijing"],"guide_type":"city-guide"}}
]
```

Validate exact field names against the generated schema and `example` records before publishing. Examples are illustrative structure, not current travel instructions. The Gallery's disposable fixture exercises the new variants with actual WordPress Media, related posts, duplicate headings and a long article; it never enters production packages.

Destination data is separate from page presentation. See `contracts/destination-catalog.schema.json` and the bundled nine-record `wp-content/plugins/solo-to-china-tools/data/destinations-v1.json` as a complete import example. Send only sourced VERIFIED fields; omit unknown arrival details or label them UNKNOWN. Do not confuse a postal address with a visitor entrance or vehicle drop-off. WordPress administrator permissions are required for catalog import/rollback; ordinary article publishing permissions do not grant this operation.

Deployment order: parent, child, tools, cache purge, runtime smoke tests, then CMS contract refresh and a draft publish/readback. Existing pages, approved Planner destination and administrator-edited content are preserved. Optional ticket rules/deep links and wider catalog coverage need content review; the schemas do not manufacture those facts.
